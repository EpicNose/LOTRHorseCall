# [LOTR 召之马来] LOTR Callable Horse 模组介绍与使用手册

> **适配环境**：Minecraft 1.7.10 (Forge 10.13.4.1614 及以上)  
> **适用魔戒版本**：LOTR 传承版 (Legacy v36.14 / v36.15) & LOTR 重制版 (Reworked 1.3.8)  
> **服务端兼容性**：标准 Forge 服务端、Crucible、Thermos、KCauldron 等主流混合端 100% 兼容  
> **构建架构**：纯净 Forge Mod（**零 Mixin / 零 UniMixins** 依赖，即装即用）

---

## 📖 一、 模组概述与核心设计

**「LOTR 召之马来 (LOTR Callable Horse)」** 是一款专为《魔戒 (The Lord of the Rings)》模组设计的高性能随身坐骑管理与战术召唤系统。

在广袤的中土大陆探险中，坐骑是玩家最忠实的伙伴。然而，原版魔戒坐骑往往面临**迷路走失、坠崖卡死、被怪物击杀、跨维度无法携带、以及随处停放导致服务器实体过多卡顿**等痛点。

本模组为玩家打造了属于自己的**「中土专属随身载具库」**：
- 随时随地将野外驯服的强力坐骑收入个人专属空间；
- 在任何战斗、赶路时刻一键召唤到身旁；
- 遇到险情或需要下线时一键无损召回；
- 坐骑的**血量、装备（鞍、马铠、座狼铠）、移速、跳跃力、名字甚至外观变种全部无损封存与恢复**！

## 🎮 三、 玩家核心操作指南

### 1. 登记新载具 (`/addhorse`)
- **操作方式**：
  1. 骑乘在你驯服好的坐骑上，或者站在可骑乘生物身旁（3 格范围内）；
  2. 在聊天栏输入指令 `/addhorse` 即可完成登记；
- **状态变化**：
  - 成功登记后，世界中的原生物将安全化为流光收纳进您的随身载具库中；
  - 坐骑身上的**装备、鞍、剩余生命值、最大血量、移速、跳跃高度、自定义名字**完整存档；
  - 聊天栏将提示登记成功及当前已占用卡槽数。

### 2. 打开载具管理界面 (GUI)
- **打开方式**：
  - 按下快捷键（默认为 **H 键**，可在 `按键控制` 中自由更改）；
  - 或在聊天栏输入管理指令 `/lotrmount`；
- **界面功能区说明**：
  - **3D 动态模型展示区**：支持鼠标光标悬停、实时 360° 旋转观察坐骑外观；
  - **典雅羊皮纸属性卡片**：位于模型右侧，清晰显示载具编号（如 `【 载具 1 / 4 】`）、当前出战状态（`出战中` / `待命中`）、生命值、移动速度、跳跃高度等动态数据；
  - **左右翻页箭头**：若登记了多个坐骑，点击即可自由轮换切换；
  - **功能按钮**：
    - **【召唤】**：将当前选中的坐骑召唤至身旁；若该坐骑已在当前世界出战，则直接将它传唤飞奔到您身边（杜绝原地不动）；
    - **【收回】**：将出战中的坐骑安全收回库中，并保留当前作战剩余生命值；
    - **【销毁】**（红字警示）：彻底注销并释放当前卡槽的载具数据。

## ⚙️ 四、 工业级安全与存储可靠性

为了在大型多人服务器中杜绝刷物、丢马、删档等隐患，模组内置了严密的底层保护机制：

1. **三级容灾备份系统**：
   - 玩家载具数据独立保存于单玩家 `.dat` 文件中；
   - 写入前先生成 `.dat.tmp` 临时文件，校验成功后安全覆盖；
   - 覆盖前自动生成 `.dat.bak` 双重备份轮转；
   - 遇到服务器异常断电或存储损坏时，**自动触发故障回退自愈机制**，绝不静默清空档案。
2. **防刷物与容器安全闭环**：
   - 当载具被收回或死亡归档时，系统会自动强行关闭所有正在查看该坐骑背包的玩家界面，彻底封堵利用界面延迟刷取装备的漏洞。
3. **区块卸载与离线安全接管**：
   - 移除老旧版本中“玩家走开 15 米强行删马”的破坏性设定；
   - 当载具所在区块卸载、或者主人退出游戏时，系统会自动将活动中的坐骑安全召回随身库，杜绝坐骑沦为区块孤儿实体。

## ⌨️ 五、 完整指令系统大全

模组核心主指令为 `/lotrmount`（别名 `/lotrhorse`）：

### 1. 玩家常用指令
| 指令 | 权限 | 说明 |
| :--- | :--- | :--- |
| `/addhorse` | 所有玩家 | 登记当前骑乘或身旁的坐骑入库 |
| `/lotrmount` | 所有玩家 | 打开个人坐骑管理与召唤 GUI 界面 |

### 2. 个人卡槽上限管理 (`/lotrmount limit`)
每个玩家默认拥有 **3** 个载具卡槽，创造模式玩家或管理员可在游戏内按需动态调整（范围 `1 ~ 100`）：
| 指令格式 | 权限 | 说明 |
| :--- | :--- | :--- |
| `/lotrmount limit` | 所有玩家 | 查看自己当前的载具存储上限与已用情况 |
| `/lotrmount limit <玩家名>` | 所有玩家 | 查询目标玩家的卡槽已用数与上限详情 |
| `/lotrmount limit [数量]` | 创造模式 / OP | 设置自己的载具存储上限（如 `/lotrmount limit 5`） |
| `/lotrmount limit <玩家名> <数量>` | 创造模式 / OP | 修改目标玩家的载具存储上限（如 `/lotrmount limit Steve 8`） |
| `/lotrmount limit <玩家名> reset` | 创造模式 / OP | 重置目标玩家的上限，重新跟随全局默认配置 |

### 3. 全局召唤冷却管理 (`/lotrmount cooldown`)
| 指令格式 | 权限 | 说明 |
| :--- | :--- | :--- |
| `/lotrmount cooldown` | 所有玩家 | 查询当前服务端的全局召唤冷却时间（默认 60 秒） |
| `/lotrmount cooldown <秒数>` | 创造模式 / OP | 动态调整全局冷却时间（0-3600 秒，设为 `0` 即可关闭冷却），立即存盘生效 |
| *特权说明* | 创造模式玩家 | **创造模式玩家享有免 CD 特权**，无论配置多少秒均可无冷却秒召！ |

### 4. 服务端操作审计日志 (`/lotrmount log`)
为方便管理员审计防刷与追踪玩家的违规行为，模组支持详细操作日志：
| 指令格式 | 权限 | 说明 |
| :--- | :--- | :--- |
| `/lotrmount log` 或 `/lotrmount log status` | 所有玩家 | 查询当前服务端审计日志的上报状态（开启/关闭） |
| `/lotrmount log on` | 创造模式 / OP | 开启玩家载具操作（登记、召唤、召回、销毁）详细后台日志 |
| `/lotrmount log off` | 创造模式 / OP | 关闭操作日志上报，减少控制台输出 |

### 5. 管理员测试体检工具 (`/lotrmount test`)
| 子指令 | 权限 | 说明 |
| :--- | :--- | :--- |
| `/lotrmount test info` | 创造模式 / OP | 一键扫描诊断当前环境魔戒已注册的可骑乘生物品类与数量 |
| `/lotrmount test dryrun` | 创造模式 / OP | 在内存中对全系生物执行无损序列化、反序列化与预览体检 |
| `/lotrmount test fill` | 创造模式 / OP | 自动向当前玩家卡槽注入全品类坐骑测试样本（免抓怪） |
| `/lotrmount test clear` | 创造模式 / OP | 一键安全清空自己的所有测试载具卡槽 |

## 🔧 六、 配置文件说明 (`lotrcallablehorse.cfg`)

首次启动后，服务端与客户端的 `config/lotrcallablehorse.cfg` 将自动生成全中文注释的配置文件：

```properties
# Configuration file

general {
    # 超过此距离时自动强制召回坐骑并入库（格数）。设为 0 表示禁用该功能，保持自由活动沉浸体验 (默认值: 0)
    I:autoRecallDistance=0

    # 是否将玩家的载具操作（登记、召唤、召回、销毁）详细上报记录到服务端Log日志中，方便管理员审计与追踪 (默认值: true)
    # 也可在游戏中使用命令动态切换: /lotrmount log <on|off>
    B:logPlayerOperations=true

    # 每位玩家默认拥有的最大载具存储卡槽数量。管理员可通过游戏内指令 /lotrmount limit 单独为指定玩家自定义上限 (默认值: 3, 范围: 1-100)
    I:maxVehicleSlots=3

    # 载具召唤冷却时间（秒）。设为 0 表示无召唤冷却。创造模式玩家默认享有免 CD 特权 (默认值: 60)
    # 也可在游戏中使用命令动态调整: /lotrmount cooldown <秒数>
    I:summonCooldownSeconds=60
}
```

## ❓ 七、 常见问题排查 (FAQ)

1. **Q：为什么在纯原版客户端或单人游戏中也能使用吗？**  
   - **A**：完全支持！模组支持单人离线存档、局域网联机以及大型多人服务端，均可无缝使用。
2. **Q：召唤出来的生物被击杀会怎样？**  
   - **A**：如果坐骑不幸战死，它的装备与物品不会直接掉在地上被敌人掠夺，系统会在它阵亡瞬间自动将装备状态完好保存在卡槽中，玩家在冷却结束后仍可重新召唤复原！
3. **Q：魔戒从旧版升级或者换周目，玩家的数据会丢失吗？**  
   - **A**：不会。模组拥有独立的命名空间与自愈机制，即使更换了客户端或升级了服务端，玩家的坐骑数据依然安全保存在独立存档中。
